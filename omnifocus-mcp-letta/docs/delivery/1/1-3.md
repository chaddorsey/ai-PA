## Requirements

### Functional Requirements
1. **Multi-Dimensional Filtering**: Support date, duration, status, project, and tag filtering
2. **Date Range Queries**: `dueBefore`, `dueAfter`, `deferBefore`, `deferAfter` parameters
3. **Duration Filtering**: `minDuration`, `maxDuration` for estimated duration filtering
4. **Status Filtering**: `flagged`, `completed`, `blocked` boolean filters
5. **Combined Filtering**: Support multiple filter criteria simultaneously

### Non-Functional Requirements
1. **Performance**: Efficient filtering with large task databases
2. **Memory Usage**: Minimal memory overhead during filtering operations
3. **Response Time**: Complete complex queries within 2 seconds

### Technical Requirements
1. **OmniFocus API**: Use native OmniFocus database queries where possible
2. **Error Handling**: Robust error handling for invalid parameters and edge cases
3. **Data Consistency**: Ensure consistent filtering behavior across all criteria

## Implementation Plan

### Phase 1: Core Method Structure
1. **Add queryTasks method**: Create method in `lib` object with parameter destructuring
2. **Parameter validation**: Validate and normalize input parameters
3. **Base task collection**: Get all tasks or filter by project/tag if specified

### Phase 2: Filtering Implementation
1. **Date filtering**:
   ```javascript
   if (params.dueBefore) tasks = tasks.filter(t => t.dueDate && t.dueDate < params.dueBefore);
   if (params.deferBefore) tasks = tasks.filter(t => t.deferDate && t.deferDate < params.deferBefore);
   ```

2. **Duration filtering**: Filter by estimatedMinutes property
3. **Status filtering**: Apply flagged, completed, blocked filters
4. **Performance optimization**: Use efficient filtering strategies

### Phase 3: Response Formatting and Integration
1. **Response formatting**: Use existing `formatTask` helper for consistency
2. **Error handling**: Handle edge cases and invalid parameter combinations
3. **Integration testing**: Test with request routing mechanism
