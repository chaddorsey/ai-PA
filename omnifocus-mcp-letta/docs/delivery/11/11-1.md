# 11-1 Audit OmniFocus planned date support

## Description
Investigate OmniFocus automation APIs to confirm `plannedDate` and `effectivePlannedDate` availability for tasks and determine serialization touchpoints in the existing MCP plugin/server.

## Requirements
- Confirm Omni Automation Task properties for `plannedDate` and `effectivePlannedDate`.
- Document which serializers (tasks, projects, perspectives, etc.) require planned date inclusion.
- Identify minimum OmniFocus version requirement.

## Implementation Plan
- Review Omni Automation documentation and test sample tasks in OmniFocus 4.7.1+.
- Inspect plugin serializers to locate injection points.
- Summarize findings in task notes for downstream implementation tasks.

## Findings
- Omni Automation `Task` objects expose writable `plannedDate` and read-only `effectivePlannedDate` properties (added in v4.7.1). No equivalent properties exist on projects, folders, or tags, so scope is limited to task serializers.[[1]](https://www.omni-automation.com/omnifocus/task.html)
- Plugin touchpoints requiring updates:
  - `serializeTask` (primary task payloads) and any helpers that duplicate task serialization (e.g., project hierarchy responses, task conversion outputs).
  - Task-centric commands in `omnifocus-mcp.omnijs` such as `listRemaining`, task lookup, conversions (`convertTaskToProject`, `moveTask`, etc.) where serialized task objects are returned.
- MCP TypeScript side must mirror task model changes only; existing project/folder interfaces remain unaffected.
- Minimum supported OmniFocus version for planned date exposure should be documented as 4.7.1+, matching API availability.
