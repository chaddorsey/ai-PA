# [3-7] Add task group type management for parent tasks

[Back to task list](./tasks.md)

## Description

Implement task group type management functions that control whether subtasks within a parent task complete in parallel (independently) or sequential (dependency chain) mode. This provides granular control over subtask completion workflows within complex task hierarchies.

## Requirements

### Core Functionality
1. **getTaskGroupType**: Read the current group type for a parent task
   - Returns 'parallel' or 'sequential' based on task.sequential property
   - Include task validation and error handling
   - Support lookup by task name or ID
   - Only applicable to tasks with subtasks

2. **setTaskGroupType**: Set the group type for a parent task
   - Accept 'parallel' or 'sequential' values
   - Map to task.sequential boolean property (false = parallel, true = sequential)
   - Validate task exists, is accessible, and has subtasks
   - Provide confirmation of change

### Technical Requirements
- Use existing task lookup patterns from previous implementations
- Follow established error handling and validation patterns
- Integration with OmniFocus task.sequential property [[memory:951370812481159986]]
- Proper caching for performance optimization

### Data Integrity Requirements
- Validate task exists and has subtasks before modification
- Handle read-only or protected tasks gracefully
- Ensure group type changes don't break existing subtask relationships

## Notes

### API Mapping
- OmniFocus `task.sequential = true` → Bridge returns `'sequential'`
- OmniFocus `task.sequential = false` → Bridge returns `'parallel'`
- This provides intuitive string-based API while leveraging boolean property underneath

### Parent Task Requirements
- Functions only work on tasks that have subtasks (parent tasks)
- Tasks without subtasks will receive appropriate error messages
- This maintains clarity about which tasks support group type configuration

### Subtask Workflow Types
1. **sequential**: Subtasks form dependency chain
   - First subtask must complete before second becomes available
   - Enforces order and dependencies
   - Best for: Multi-step processes, approval workflows

2. **parallel**: Subtasks can complete independently
   - All subtasks available immediately
   - No completion dependencies
   - Best for: Collaborative work, independent activities
