## Example MCP Calls

- **Initialize session**
  - `curl -i -s -X POST http://localhost:8889/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","id":"init","method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{"tools":{}},"clientInfo":{"name":"docs-example","version":"1.0.0"}}}'`
  - Capture the `mcp-session-id` response header; reuse it for subsequent requests.
- **projectOperations.get (detailLevel: standard)**
  - `curl -s -X POST http://localhost:8889/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -H "mcp-session-id: <SESSION_ID>" -d '{"jsonrpc":"2.0","id":"project-get-standard","method":"tools/call","params":{"name":"projectOperations","arguments":{"action":"get","parameters":{"projectId":"<PROJECT_ID>"},"detailLevel":"standard"}}}'`
  - Sample response excerpt:

```
{
  "result": {
    "id": "fKQZJCtFOZd",
    "completionState": "active",
    "folderId": "bsA6lksznTk",
    "folderName": "Daily Routine",
    "added": "2021-10-29T13:26:25.642Z",
    "modified": "2025-08-11T14:51:00.316Z",
    "taskCounts": { "total": 12, "completed": 0, "active": 12, "remaining": 12 }
  }
}
```

- **listProjects (detailLevel: full, grouped by folder)**
  - `curl -s -X POST http://localhost:8889/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -H "mcp-session-id: <SESSION_ID>" -d '{"jsonrpc":"2.0","id":"listProjects-full","method":"tools/call","params":{"name":"listProjects","arguments":{"detailLevel":"full","listByFolder":true}}}'`
  - Response includes folder envelopes:

```
[
  {
    "folderId": "epDSRHIqyN4",
    "folderName": "On Tap",
    "projects": [
      {
        "id": "bdRrScFC2eT",
        "taskCounts": { "total": 167, "active": 61 },
        "tasks": [
          {
            "id": "bGoS_qQI79A",
            "name": "Determine person for Valhalla coaching request",
            "added": "2025-03-26T05:45:55.832Z",
            "durationMinutes": 30
          }
        ]
      }
    ]
  }
]
```

- **completion filters**
  - Use `"completion":"completed"` or `"completion":"dropped"` to scope results; the payload retains timestamps and counts while pruning active projects.
- Responses include `durationMinutes` when available (null when not set).
- Minimal responses (`"detailLevel":"minimal"`) retain `{ id, name, completed, flagged, added, modified, durationMinutes }` for lightweight integrations.
- **List uncompleted tasks for a project**
  ```
  {"jsonrpc":"2.0","id":"tasks","method":"tools/call","params":{"name":"listUncompletedTasks","arguments":{"projectId":"hyuhFPao76Z"}}}
  ```

## Tips

- `detailLevel` determines field richness (`minimal`, `standard`, `full`).
- `completion` accepts `all`, `active`, `completed`, `dropped`.
- Prefer `listByFolder:true` when presenting hierarchical summaries.
- Refer to project metadata docs for field descriptions.
- Use `tasksHelp` for quick reference from MCP clients.
