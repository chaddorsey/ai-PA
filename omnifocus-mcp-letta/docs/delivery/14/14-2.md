## Requirements
- Add handler for `markTaskCompleted` accepting `taskId`.
- Add handler for `moveTaskToProject` accepting `taskId` and `projectId`.
- Validate existence of referenced entities; return errors when invalid.
- Reuse transaction/bridge helpers to perform operations.
- Return success payloads with task/project IDs and updated status indicators.
// Completed Enhancements
- Registered four quick-access tools (`markTaskCompleted`, `listUncompletedTasks`, `listProjects`, `moveTaskToProject`) in `server-mcp-simplified.ts` with dedicated JSON schemas.
- Added helper utilities for string validation, task availability checks, task/project summary shaping, and folder grouping.
- Implemented early-return handlers:
  - `markTaskCompleted` delegates to `completeTask` and returns `{ taskId, completionStatus, completedAt, alreadyCompleted? }`.
  - `moveTaskToProject` calls `moveTask` and returns `{ taskId, projectId, status: "moved" }`.
  - `listUncompletedTasks` filters `listRemaining` output by optional `projectId`, `onlyFlagged`, `onlyAvailable` parameters and returns normalized task summaries.
  - `listProjects` hydrates project summaries with optional task names and folder-grouped results.
- Ensured available-status filter matches OmniFocus semantics (not completed/dropped and no future defer date).
