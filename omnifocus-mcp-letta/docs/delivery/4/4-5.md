# 4-5 Implement task-to-project conversion

[Back to task list](./tasks.md)

## Description

Implement the capability to convert existing tasks into projects, with options for preserving subtasks and controlling the placement of the new project within the folder structure. This enables dynamic promotion of tasks to project status as work scope evolves.

## Requirements

### Functional Requirements
1. **Task-to-Project Conversion**: Convert existing tasks into full projects
2. **Subtask Preservation**: Option to preserve existing subtasks as project tasks
3. **Folder Placement**: Control where the new project is placed in folder structure
4. **Property Transfer**: Transfer relevant task properties to the new project
5. **Relationship Management**: Handle conversion of tasks with complex relationships

### Technical Requirements
1. **OmniFocus Plugin Extension**: Add task conversion methods to plugin
2. **Data Migration**: Seamless transfer of task data to project structure
3. **Relationship Handling**: Manage parent/child relationships during conversion
4. **Transaction Safety**: Ensure atomic conversion operations

### Integration Requirements
1. **Dependency on Tasks 4-1, 4-4**: Requires folder and project management
2. **Bridge Consistency**: Follow established task and project manipulation patterns
3. **Relationship Integrity**: Maintain data integrity during conversion

## Implementation Plan

### Phase 1: OmniFocus Plugin Development
1. **Research Task-to-Project API**: Study OmniFocus task conversion capabilities
2. **Implement Core Methods**:
   - `convertTaskToProject(taskId, folderId?, preserveSubtasks?)`
   - `getTaskSubtasks(taskId)`
   - `validateTaskConversion(taskId)`
3. **Property Migration**: Transfer task properties to project properties
4. **Test Plugin Methods**: Direct testing of task conversion

### Phase 2: Bridge Layer Integration
1. **Extend Bridge Interface**: Add task conversion methods
2. **Implement Type Definitions**: Define interfaces for conversion operations
3. **Data Migration Logic**: Handle property and relationship transfers
4. **Validation Logic**: Pre-conversion validation and safety checks

### Phase 3: MCP Server Integration
1. **Register MCP Tools**:
   - `convertTaskToProject`: Convert task with folder and subtask options
   - `previewTaskConversion`: Show what would happen before conversion
   - `validateTaskConversion`: Check if task can be converted
2. **Implement Tool Handlers**: Handle MCP calls and route to bridge
3. **Response Formatting**: Format conversion results for AI consumption

### Phase 4: Testing and Validation
1. **Unit Tests**: Test task conversion methods in isolation
2. **Integration Tests**: Test conversion through complete stack
3. **Relationship Testing**: Test conversion with various task relationships
4. **Manual Verification**: Verify conversion in actual OmniFocus
