# Salvage map (Unit C2, R22)

Every source file of the two built packages — `clients/letta-continuity-core/` and
`clients/letta-terminal/` — plus the four shared tools in `clients/tools/`, assigned to exactly
one destination: **controller-side**, **surface-side**, or **retire**. Assignments were made by
reading each file, not by name. Mutation-harness entries guarding retiring code are enumerated
for retirement in the final section.

## Summary

| Destination | Files | Meaning |
|---|---|---|
| controller-side | 33 | Evolves in place into the controller's App-Server client library (+ its test/tooling assets) |
| surface-side | 19 | Stays with the terminal surface; also the pinned emergency break-glass direct client |
| retire | 5 | Deleted (staged where the break-glass path still compiles against them — see flags) |
| **total** | **57** | every source file in both packages + `clients/tools/` appears exactly once below |

Mutation harness: **81 entries** → **65 keep**, **16 retire** (listed by id and label below).

## Carried recommendation: evolve `letta-continuity-core` in place

Confirmed against the code. The package's README role ("raw-WS client core for the sole-owner
App Server; speaks the full `/ws` protocol on one ordered connection") is exactly the
controller's App-Server client library — only the *consumer* changes (the resident controller
instead of N peer surfaces). Evolving in place keeps the mutation history in
`clients/tools/mutations.mjs` attached to the code it guards; a fork would orphan all 81
bindings at once. The `exports` map (`.`, `./protocol`, `./pointer`, `./testing`,
`./testing/harness`) already gives Unit C3's `src/app-server-client/` a clean import seam.

## Operator decision 2026-08-15: the break-glass direct path

The terminal's direct raw-WS transport is **not retired** — it stays installable as the
emergency client that can attach to the App Server with the controller down. This concretely
pins the following files in place (they must keep compiling and working as a direct client
alongside the new controller transport):

- **Terminal:** `src/main.ts`, `src/cli.ts`, `src/session.ts`, `src/render.ts`,
  `src/sanitize.ts`, `bin/letta-continuity` (deploy wrapper → `~/bin/letta-continuity`).
- **Core (consumed by the direct path):** `src/index.ts` (ContinuityCore facade), `src/ws.ts`,
  `src/protocol.ts`, `src/stream.ts`, `src/connection.ts`, `src/catchup.ts`, `src/trust.ts`,
  `src/fanout.ts`, `src/evict.ts`.

Consequence: the two retiring core modules the direct path still imports (`ownership.ts` via
the facade, `pointer.ts` via `--pointer` targeting and `conversations create --write-pointer`)
get **staged** retirement — removed only when C6 rebinds the terminal to controller-stamped
origin data and the break-glass path is re-based on explicit `--agent`/`--conversation`
targeting (both flags already exist and bypass the pointer entirely). Until that lands, both
files remain in the tree but are frozen: no new consumers.

## Judgment calls flagged to the operator

1. **Staged retirement of `ownership.ts` and `pointer.ts`.** Both are marked retire per the
   plan, but the pinned break-glass direct path compiles against them today (facade wiring,
   terminal one-shot `sawOurTurn` guard, `--pointer` targeting). Recommendation: freeze now,
   delete in C6 when the terminal rebinds — break-glass then targets via `--agent`/
   `--conversation` and accepts degraded (absent) peer/self labels in direct mode.
2. **`transport.compile.test.ts` retired.** The browser-transport compile guarantee served the
   superseded peer-client web surface. If any future consumer must implement
   `ContinuityTransport` outside Node, this test should be resurrected from history rather than
   rewritten.
3. **`capture-ownership.mjs` kept (controller-side) despite its retiring namesake.** Judged by
   content: it is the only live frame-capture rig with ordering-readable logs; rename it
   (`capture-ws.mjs` or similar) when first touched so the name stops pointing at a dead design.
4. **Mutation 10 (per-origin correlation nonce) retired.** The nonce machinery in `protocol.ts`
   (`newClientNonce`, per-send nonce parameter) stays — the controller as sole submitter still
   wants distinguishable correlation ids per surface — but the *property this entry binds*
   ("ownership can tell which browser a run belongs to") is attribution, which retires. If C4's
   journal reuses per-origin nonces, it should add its own entry.
5. **Entries 32/33/36 kept rather than retired** even though they touch attribution call sites —
   the observable behaviors (one-shot terminates on idle not own-run-finish; unlabellable runs
   render as `unknown`, never confidently `self`) survive on the break-glass path and must keep
   failing when reverted.
