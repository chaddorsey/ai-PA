# LettaBot pa-web-ui Integration Design

**Date**: 2026-03-12
**Status**: Approved

## Overview

Integrate LettaBot as the default chat backend for pa-web-ui, replacing the main Letta agent for general conversation. Specialized agents remain accessible via slash commands through the existing routing handler. LettaBot's heartbeat provides proactive background work and time awareness.

## Architecture

### Default Path (no slash command)

```
User message → pa-web-ui /stream → LettaBot /api/v1/chat (native SSE)
                                         ↓
                                    Letta Code agent responds
                                         ↓
                                    SSE stream → frontend
```

### Slash Command Path (`/calendar`, `/tasks`, `/main`, etc.)

```
User message → pa-web-ui /stream → pa-routing-handler /v1/route → Letta agent
                                         ↓                              ↓
                                    SSE stream → frontend    Async summary → LettaBot
```

### Key Decisions

- **LettaBot is the default** for all non-slash messages
- **Kill keyword/contextual auto-routing** — slash commands only for sub-agents
- **`/main`** becomes a slash command to access the old main agent directly
- **Slash-routed responses** post an async summary to LettaBot via `/api/v1/chat/async`
- **LettaBot manages its own conversation state** — lightweight log to pa_web.conversations for UI history only
- **Heartbeat activity** appears as collapsible messages in the chat feed

## SSE Format Translation

Use LettaBot's **native `/api/v1/chat`** endpoint (not OpenAI-compatible) for rich event streaming.

| LettaBot native event | → | pa-web-ui frontend event |
|---|---|---|
| `tool_call` | → | `tool_call` |
| `tool_result` | → | `tool_result` (collapsible) |
| `reasoning` | → | `thinking` |
| `assistant` | → | `text` |
| `result` | → | `done` |
| `error` | → | `error` |

A synthetic `routing` event is emitted at stream start with agent name "LettaBot".

## Slash Command Routing

- Frontend detects slash commands (`/calendar`, `/tasks`, `/main`, `/docs`, etc.)
- Slash commands route through pa-routing-handler → specific Letta agent (existing pipeline)
- All other messages go to LettaBot
- Keyword and contextual auto-routing is disabled

## Summary Posting

After a slash-routed agent completes its response:
- Async POST to LettaBot `/api/v1/chat/async` with a summary:
  ```
  [System: Agent handoff summary] The user invoked /calendar and asked: "..."
  Calendar Agent responded: "<first ~500 chars of response>"
  ```
- Fire-and-forget (202 response), does not block UI
- LettaBot absorbs into its persistent memory

## Heartbeat Integration

Heartbeat is enabled and runs at configurable intervals (default 30 min).

**Behavior**:
- Agent receives silent prompt with current time, timezone, and actionable todos
- Agent decides whether to take action (run tools, send reminders, etc.)
- Skips if user messaged within last 5 minutes

**Web UI Display**:
- Heartbeat activity appears as collapsible messages in the chat feed
- Visually distinct from user/assistant messages (muted styling, heartbeat indicator)
- Expandable to show tool calls and results
- Sourced from LettaBot's `/turns/stream` (filtered for `trigger: 'heartbeat'`)
- Recent heartbeats loaded from `/turns/data` on page load

## Conversation Persistence

- LettaBot manages conversation state internally (Letta agent memory)
- pa-web-ui saves lightweight log entries to `pa_web.conversations` for UI history
- No double-tracking of state — LettaBot is the source of truth
- Existing pa_web conversation tracking remains for slash-routed agent messages

## Configuration

### lettabot.yaml
```yaml
server:
  mode: docker
  baseUrl: http://localhost:8283

agents:
  - name: LettaBot
    conversations:
      mode: shared
      heartbeat: last-active
    channels:
      telegram:
        enabled: true
        token: <from env>
        dmPolicy: open

features:
  cron: false
  heartbeat:
    enabled: true
    intervalMin: 30
    skipRecentUserMin: 5
```

### pa-web-ui environment
```
LETTABOT_API_URL=http://localhost:8080
LETTABOT_API_KEY=<auto-generated or from env>
```

## Components Modified

| Component | Changes |
|---|---|
| `pa-web-ui/app.py` | New LettaBot proxy in `/stream`, slash command detection, summary posting, heartbeat feed endpoint |
| `pa-web-ui/static/js/chat.js` | Slash command parsing (remove keyword routing), heartbeat message rendering, tool_result display |
| `pa-web-ui/templates/index.html` | Heartbeat message styling |
| `pa-routing-handler` | No changes — slash commands use existing routing with explicit agent_id |
| `lettabot/lettabot.yaml` | Enable heartbeat |

## Future Considerations

- Deprecate pa_web conversation tracking once LettaBot proves reliable
- Evaluate LettaBot cron vs. scheduler-service overlap
- Multi-agent teams may obviate current routing architecture
- Activity feed panel for deeper heartbeat/background work visibility
- LettaBot Slack channel integration (deferred)
