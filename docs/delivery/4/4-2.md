## Description

## Requirements

### Functional Requirements
1. **Project Movement**: Move existing projects from one folder to another
2. **Position Control**: Specify the position within the target folder
3. **Root Level Support**: Support moving projects to/from root level (no folder)
4. **Validation**: Verify project and folder existence before movement
5. **Relationship Preservation**: Maintain all project properties and task relationships

### Technical Requirements
1. **OmniFocus Plugin Extension**: Add project movement methods to plugin
2. **Position Management**: Handle project ordering within folders
3. **Transaction Safety**: Ensure atomic project movement operations
4. **Error Recovery**: Graceful handling of movement failures

### Integration Requirements
1. **Dependency on Task 4-1**: Requires folder management infrastructure
2. **Bridge Consistency**: Follow established project manipulation patterns
3. **MCP Tool Integration**: Expose movement capabilities through MCP interface

## Implementation Plan

### Phase 1: OmniFocus Plugin Development
1. **Research Project Movement API**: Study OmniFocus project container management
2. **Implement Core Methods**:
   - `moveProject(projectId, targetFolderId?, position?)`
   - `getProjectPosition(projectId)`
   - `validateProjectMove(projectId, targetFolderId)`
3. **Handle Edge Cases**: Root level moves, position boundaries
4. **Test Plugin Methods**: Direct testing of project movement

### Phase 2: Bridge Layer Integration
1. **Extend Bridge Interface**: Add project movement methods
2. **Implement Type Definitions**: Define interfaces for move operations
3. **Add Validation Logic**: Pre-move validation and safety checks
4. **Position Management**: Logic for calculating and managing positions

### Phase 3: MCP Server Integration
1. **Register MCP Tools**:
   - `moveProject`: Move project to specified folder and position
   - `getProjectLocation`: Get current folder and position of project
2. **Implement Tool Handlers**: Handle MCP calls and route to bridge
3. **Response Formatting**: Format move operation results for AI consumption

### Phase 4: Testing and Validation
1. **Unit Tests**: Test project movement methods in isolation
2. **Integration Tests**: Test movement through complete stack
3. **Edge Case Testing**: Root level moves, invalid positions, non-existent targets
4. **Manual Verification**: Verify movement in actual OmniFocus application

## Verification

### Test Plan

2. **Position Control**:
   - Move project to specific position within folder
   - Verify correct ordering among projects
   - Test first, last, and middle positions

3. **Root Level Operations**:
   - Move project from folder to root level
   - Move project from root level to folder
   - Verify root level project handling

4. **Validation Testing**:
   - Test moving non-existent project
   - Test moving to non-existent folder
   - Test invalid position values
   - Verify appropriate error messages

5. **Relationship Preservation**:
   - Verify all tasks remain with project after move
   - Confirm project metadata is preserved
   - Test that project dependencies are maintained

### Success Criteria

- Projects appear in correct target locations
- Position control works as specified
- All project properties and relationships are preserved
- Validation prevents invalid operations
- Error handling provides clear feedback
