## Requirements

1. **Tool Functions to Define** (following Letta custom tool conventions):
   - `create_calendar_event()`: Create new calendar events
   - `get_calendar_events()`: Retrieve events within date range
   - `get_calendar_event()`: Retrieve single event by ID
   - `update_calendar_event()`: Update existing events
   - `delete_calendar_event()`: Delete events
   - `list_calendars()`: List accessible calendars

2. **Function Structure** (CRITICAL - see `context/coding_custom_letta_tools.md`):
   - Module-level imports ONLY for type hints: `from typing import Dict, Any, Optional, List`
   - All runtime imports inside function at the very beginning (before any other code)
   - No nested `def` statements - all helper logic must be inlined
   - Use lambdas for simple operations (sorting, filtering)
   - Entire function wrapped in try-except
   - Return `Dict[str, Any]` with consistent structure

3. **Input Parameters** (typed parameters, not Pydantic models):
   - Comprehensive parameter definitions with type hints
   - Default values where appropriate using `Optional[...] = None` pattern
   - Required vs optional parameters clearly marked
   - Validation rules documented in docstring (e.g., ISO 8601 datetime format)

4. **Return Format** (Dict[str, Any]):
   - Consistent structure: `{"status": "ok" | "error", ...tool-specific data..., "error_message": ...}`
   - Success response includes relevant data
   - Error response includes `error_message` field

5. **Docstrings**: Each function should have:
   - Clear description of what the tool does
   - `Args:` section with parameter descriptions (types and defaults)
   - `Returns:` section describing return dictionary structure
   - Example usage (optional but helpful)
   - Error conditions documented

6. **Type Hints**: Full type annotations for all parameters and return values (`-> Dict[str, Any]`)
