# [25-7] Implement delete event tool

## Description
Implement `delete_calendar_event()` tool to delete calendar events with support for controlling whether update notifications are sent to attendees.

## Requirements

1. **Function**: `delete_calendar_event()` with parameters:
   - `calendar_id` (str, required): Calendar ID (email) or "primary"
   - `event_id` (str, required): Event ID of event to delete
   - `send_updates` (str, optional): "all", "externalOnly", or "none", default "all"

2. **API Call**: Use `events.delete()` method
   - Include `sendUpdates` parameter

3. **Response Format**:
   - Success confirmation with:
     - Status indicator (success)
     - Message confirming deletion
     - Event ID that was deleted
   - Error response with clear error message if failed

4. **Error Handling**:
   - Handle event not found
   - Handle invalid event ID
   - Handle permission errors (no delete access)
   - Handle invalid calendar ID
   - Provide clear error messages

5. **send_updates Behavior**:
   - `"all"`: Send cancellation emails to all attendees
   - `"externalOnly"`: Send cancellation emails only to external attendees
   - `"none"`: Do not send cancellation emails

## Implementation Plan

1. Implement `delete_calendar_event()` function following Letta conventions:
   - Module-level imports only for type hints
   - All runtime imports inside function at the very beginning
   - Inline authentication logic (from task 25-2 pattern)
   - No nested `def` statements - inline all logic
   - Entire function wrapped in try-except

2. Implement parameter validation (inline, no helper functions)

3. Call Calendar API (inline):
   - Call `service.events().delete(calendarId=calendar_id, eventId=event_id, sendUpdates=send_updates).execute()`

4. Handle API response (inline logic):
   - Delete returns empty body on success
   - Build structured success response

5. Add error handling with safe fallbacks
6. Return `Dict[str, Any]` with status and confirmation
