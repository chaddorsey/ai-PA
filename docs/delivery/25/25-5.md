# [25-5] Implement get events tool

## Description
Implement `get_calendar_events()` tool to retrieve events within a date range, and `get_calendar_event()` tool to retrieve a single event by ID. Both tools should return comprehensive event details.

## Requirements

1. **Function 1**: `get_calendar_events()` with parameters:
   - `calendar_id` (str, required): Calendar ID (email) or "primary"
   - `time_min` (str, required): ISO 8601 datetime string for start of range
   - `time_max` (str, required): ISO 8601 datetime string for end of range
   - `max_results` (int, optional): Maximum events to return, default 100
   - `single_events` (bool, optional): Expand recurring events, default True
   - `order_by` (str, optional): "startTime" or "updated", default "startTime"

2. **Function 2**: `get_calendar_event()` with parameters:
   - `calendar_id` (str, required): Calendar ID (email) or "primary"
   - `event_id` (str, required): Event ID from calendar

3. **API Calls**:
   - `get_calendar_events()`: Use `events.list()` method
   - `get_calendar_event()`: Use `events.get()` method

4. **Response Format**:
   - List of events (for `get_calendar_events()`) or single event (for `get_calendar_event()`)
   - Event objects include:
     - Event ID
     - Summary (title)
     - Start/end times with timezone
     - Description
     - Location
     - Attendees list with email and response status
     - Organizer information
     - Attachment information
     - Created/modified timestamps
   - Status indicator
   - Error message if failed

5. **Error Handling**:
   - Handle invalid calendar ID
   - Handle invalid event ID (for get_calendar_event)
   - Handle invalid date range
   - Handle permission errors
   - Handle pagination if needed

6. **Pagination**: Handle `nextPageToken` if more events available

## Implementation Plan

1. Implement `get_calendar_events()` function following Letta conventions:
   - Module-level imports only for type hints
   - All runtime imports inside function at the very beginning
   - Inline authentication logic (from task 25-2 pattern)
   - No nested `def` statements - inline all logic
   - Entire function wrapped in try-except

2. Implement `get_calendar_event()` function following same conventions

3. Implement parameter validation (inline, no helper functions)

4. For `get_calendar_events()` (inline logic):
   - Build query parameters
   - Call `service.events().list(...).execute()`
   - Handle pagination with `nextPageToken` (inline loop)
   - Transform event list to structured format

5. For `get_calendar_event()` (inline logic):
   - Call `service.events().get(calendarId=calendar_id, eventId=event_id).execute()`
   - Transform event to structured format

6. Add error handling with safe fallbacks
7. Return `Dict[str, Any]` with status and data
