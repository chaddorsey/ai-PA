## Requirements

1. **Error Response Format**: Consistent across all tools
   - `status`: "error"
   - `error_message`: Human-readable error message
   - `error_code`: Optional error code for programmatic handling
   - `error_details`: Optional additional details

2. **Input Validation**:
   - ISO 8601 datetime format validation
   - Email address validation for attendees and calendar IDs
   - Timezone validation (check against IANA timezone database)
   - Date range validation (end after start)
   - Required parameter presence checks
   - Google Drive file ID format validation for attachments

3. **API Error Handling**:
   - Handle `HttpError` from googleapiclient
   - Map HTTP status codes to meaningful error messages:
     - 404: Event/calendar not found
     - 403: Permission denied
     - 400: Invalid request parameters
     - 401: Authentication required
   - Extract error details from API response

4. **Permission Error Handling**:
   - Detect calendar sharing permission issues
   - Detect insufficient permission level (read-only vs write)
   - Provide helpful messages suggesting calendar sharing

5. **Validation Utilities**:
   - Create reusable validation functions
   - Centralize validation logic
   - Consistent validation error messages

6. **Error Logging**:
   - Log errors appropriately for debugging
   - Include context (function name, parameters)
   - Avoid logging sensitive information (email addresses OK, but not full event data)
