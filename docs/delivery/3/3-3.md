# [3-3] Enhance inbox processing with bulk operations

[Back to task list](./tasks.md)

## Description

Implement a **"Front-Loaded Intelligence with Batch Execution"** inbox processing system that maximizes AI efficiency while maintaining structured, reliable processing. This approach loads comprehensive context in a single call, empowers the AI to perform intelligent analysis locally, then executes the complete plan via batch operations - eliminating inefficient tool roundtrips while preserving user control through dual-response interfaces (shortcuts + natural language).

### **Command Processing System**

**Dual-Response Command Pattern**:

Every interface presents both shortcuts and accepts natural language:

```
Commands: (a) accept 1,2,3 | (h) hold 4,5 | (m) merge 7→1 | (e) edit 6 | (p) preview

User can respond with:
- Shortcuts: "a, m" or "h, e" 
- Natural language: "Accept items 1,2,3 and merge 7 into 1"
- Mixed: "a and merge 7 into 1"
```

**Context-Guided Interpretation**:
Natural language gets interpreted based on most recently presented options:
- After seeing "merge 7→1" option, "merge the whitening question" maps to item 7→1
- After seeing "edit 6" option, "change the project" maps to editing item 6
- Ambiguous commands default to asking for clarification with shortcuts

### **Suggestion Intelligence System**

#### **Project Inference Rules**
1. **Explicit Reference**: "Home project task" → Home Projects
2. **Content Analysis**: "Buy groceries" → Personal/Home-related projects
3. **Recency Bias**: Recently modified projects preferred
4. **Pattern Learning**: Similar historical tasks inform suggestions

- **Clarity Enhancement**: "Get noodles" → "Buy noodles at grocery store"  
- **Context Addition**: "Call dentist" → "Schedule dentist appointment"
- **Action Clarification**: "Taxes" → "Complete 2024 tax filing"
- **Original Preservation**: Always in notes as "[Original: Get noodles]"

#### **Smart Date Extraction**
- **Natural Language**: "by Friday" → due: this Friday
- **Relative Dates**: "tomorrow" → specific date  
- **Time Context**: "Monday meeting" → due: Monday 8am
- **Recurring Patterns**: "weekly review" → recurring task suggestion

#### **Continuation Item Recognition**
- **Content Analysis**: Identify items that contain supplemental information rather than standalone tasks
- **URL Detection**: `"http://example.com for the Rick foundations research"` → merge URL into related task note  
- **Project Clarification**: `"Home and garden project for the plant purchase task"` → assign related task to specified project
- **Contextual Tags**: `"@urgent @work for the meeting prep"` → add tags to related task
- **Additional Context**: `"Ask about whitening options (dentist appointment)"` → append to related task note
- **Smart Relationship Detection**: Use semantic analysis to identify which items should be merged together
- **Fuzzy Matching**: Link continuation items to target tasks even when names don't match exactly

## Approach: **Front-Loaded Intelligence with Batch Execution**

### **Core Design Principle**
**Minimize Tool Roundtrips**: Load the AI with comprehensive context in 1-2 calls, let it do the intelligent analysis locally, then execute with a single batch operation.

**Problem with Previous Approach:**
```
❌ analyzeInboxItems() → AI presents → User refines → refineInboxSuggestions() → AI presents → executeInboxProcessing() → repeat
   (5-10 tool calls per session, high latency, token waste)
```

**New Efficient Approach:**
```
✅ getInboxProcessingContext() → AI analyzes & presents complete plan → executeBulkInboxProcessing()
   (2 tool calls total, rich context, AI-driven intelligence)
```

### **Three-Phase Workflow**

#### **Phase 1: Rich Context Loading** (1 tool call)
```typescript
getInboxProcessingContext() → {
  inbox_items: Array<EnrichedInboxItem>,
  processing_intelligence: UserProcessingPatterns,
  available_destinations: ProjectTagHierarchy,
  example_processing_sessions: Array<HistoricalExample>
}
```

**Rich Context Includes:**
- **All inbox items** with extracted dates, potential projects, content analysis
- **User patterns** from recent processing history (which projects/tags they use)
- **Available destinations** with recency scores and usage frequency  
- **Success examples** showing how similar items were processed before
- **Smart suggestions** with confidence scores pre-calculated by server

#### **Phase 2: AI-Driven Analysis** (0 tool calls - pure AI processing)
The AI uses its native intelligence to:
- **Categorize items** into confidence groups using provided patterns
- **Generate suggestions** using historical examples and user patterns
- **Detect relationships** between items for merging opportunities
- **Create processing plan** with shortcuts and natural language options
- **Present dual-response interface** with embedded shortcuts

#### **Phase 3: Batch Execution** (1 tool call)
```typescript
executeBulkInboxProcessing({
  processing_plan: CompletePlan,
  user_modifications?: Array<Modification>
}) → ExecutionResult
```

## Key Efficiency Gains

1. **Single Rich Load**: Everything the AI needs in one tool call
2. **AI-Native Processing**: Leverage AI's pattern recognition instead of server logic  
3. **Batch Execution**: One operation processes the entire plan
4. **Front-Loaded Shortcuts**: AI can generate shortcuts using provided context
5. **Zero Iteration**: User sees complete analysis and can execute immediately
6. **Smart Defaults**: High-confidence items ready for immediate approval
