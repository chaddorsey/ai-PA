## Description

## Requirements

### Core Functionality  
1. **getProjectCompletionBehavior**: Read the current completion behavior for a project
   - Returns 'completeWithLastAction' or 'manual' based on project.completedByChildren property
   - Include project validation and error handling
   - Support lookup by project name or ID

2. **setProjectCompletionBehavior**: Set the completion behavior for a project
   - Accept 'completeWithLastAction' or 'manual' values
   - Map to project.completedByChildren boolean property (true = auto-complete, false = manual)
   - Validate project exists and is accessible
   - Provide confirmation of change

### Technical Requirements
- Use existing project lookup patterns from Task 3-5
- Follow established error handling and validation patterns
- Integration with OmniFocus project.completedByChildren property [[memory:951370812481159986]]
- Proper caching for performance optimization

### Data Integrity Requirements
- Validate project exists before modification
- Handle read-only or protected projects gracefully
- Ensure completion behavior changes don't affect existing project state

## Notes

### API Mapping
- OmniFocus `project.completedByChildren = true` → Bridge returns `'completeWithLastAction'`
- OmniFocus `project.completedByChildren = false` → Bridge returns `'manual'`
- This provides intuitive string-based API while leveraging boolean property underneath

### Completion Behavior Types
1. **completeWithLastAction**: Project automatically completes when final task is done
   - Best for: Projects with clear endpoints (launches, deliverables)
   - Reduces manual overhead for project closure
   
2. **manual**: Project requires explicit completion action
   - Best for: Ongoing work, maintenance projects, projects requiring sign-off
   - Ensures proper project closure procedures
