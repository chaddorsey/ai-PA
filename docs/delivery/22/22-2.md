# 22-2 Implement event fetching by ID via MCP

[Back to task list](./tasks.md)

## Description
Add function to fetch specific event by ID using MCP Core_Event_Data. Since Core_Event_Data only supports date range queries, we'll fetch events in a reasonable date range around the event's expected time, then filter by event ID. Handle errors for missing/inaccessible events.

## Requirements
- Create function `fetch_event_by_id` that takes `event_id` and `calendar_id` (participant ID)
- Use MCP Core_Event_Data to fetch events, then filter by event ID
- Since this is for rescheduling, only search current and future days (default: today to 30 days forward)
- Handle cases where event is not found (return None or raise appropriate error)
- Handle cases where event is inaccessible (permissions error)
- Handle MCP connection errors gracefully
- Return event in the same format as `get_core_event_data` (dict with id, summary, start, end, etc.)
- Update function signature to require `event_participant_id` instead of `event_owner_id` (any participant can be used)

## Implementation Plan
1. Add `fetch_event_by_id` method to `MCPCalendarClient` class in `mcp_client.py`
2. Method signature: `async def fetch_event_by_id(self, calendar_id: str, event_id: str, days_forward: int = 30) -> Optional[Dict[str, Any]]`
3. Calculate date range: from today (start of day) to (today + days_forward)
4. Call `get_core_event_data` with the date range
5. Filter results to find event with matching `id` field
6. Return the matching event dict, or None if not found
7. Handle MCP errors (connection, permissions, etc.) and return appropriate error responses
8. Update `orchestrate_scheduling` to use `event_participant_id` parameter instead of `event_owner_id`
9. Update validation and error messages to reflect participant ID requirement
10. Integrate with existing event fetching logic

## Verification
