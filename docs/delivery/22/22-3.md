# 22-3 Extend DSPy extraction for rescheduling intent

[Back to task list](./tasks.md)

## Description
Update `ExtractSchedulingRequest` signature and extraction logic to detect rescheduling intent and extract event identifiers (participant names, dates, times, titles) from natural language. This enables the tool to identify which meeting the user wants to reschedule when they use natural language instead of providing an explicit event ID.

## Requirements
- Update `ExtractSchedulingRequest` signature to detect rescheduling intent
- Extract event identifiers from natural language:
  - Participant names (e.g., "meeting with Judi")
  - Dates (e.g., "on Dec. 10th", "Monday", "next week")
  - Times (e.g., "at 2pm", "in the morning", "afternoon")
  - Event titles (e.g., "check-in", "standup", "review meeting")
- Add rescheduling intent detection keywords: "reschedule", "find new time", "move", "change time", "new time for", etc.
- Output should include:
  - `is_rescheduling`: boolean indicating if this is a rescheduling request
  - `event_identifiers`: object with extracted participant_names, dates, times, titles
- Maintain backward compatibility: existing scheduling requests should still work
- Update output field description to include rescheduling fields

## Implementation Plan
1. Update `ExtractSchedulingRequest` signature in `dspy_extraction.py`:
   - Update `utterance` field description to mention rescheduling keywords
   - Update `problem_json` output field description to include rescheduling fields
2. Update the SchedulingProblem schema (if needed) or create a wrapper that includes rescheduling metadata
3. Update extraction logic to detect rescheduling intent
4. Extract event identifiers from the utterance
5. Include rescheduling metadata in the extracted problem
6. Test with examples:
   - "Find me a new time for the check-in with Judi on Dec. 10th"
   - "Reschedule my meeting with Alex tomorrow"
   - "Move the standup to a different time"
