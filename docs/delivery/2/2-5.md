## Description

Implement essential perspective operations in the OmniFocus plugin (`omnifocus-mcp.omnijs`) to enable complete basic perspective management through AI conversations. This includes `listPerspectives` to discover available perspectives, `switchToPerspective` to navigate between them, and `listTasksByPerspective` to see tasks in any perspective, providing users with full access to both built-in perspectives (Inbox, Projects, Flagged, Forecast, etc.) and user-created custom perspectives.

**Enhanced Scope**: Added `listTasksByPerspective` to provide complete perspective workflow: list → switch → view tasks. This gives users full perspective navigation capabilities without requiring advanced CRUD operations.

**Scope Note**: This task focuses on essential perspective operations (list + switch + view tasks). Advanced perspective management (create, update, delete perspectives) has been moved to PBI-3 to prioritize more frequently used project/folder operations.

Perspectives in OmniFocus are powerful organizational views that filter and display tasks based on specific criteria. Built-in perspectives provide standard views, while custom perspectives allow users to create personalized task filtering and organization systems.

## Requirements

### Functional Requirements
1. **Built-in Perspective Access**: List all built-in perspectives (Inbox, Projects, Flagged, Forecast, Nearby, Review, Search, Tags)
2. **Custom Perspective Access**: List all user-created custom perspectives with metadata
3. **Perspective Metadata**: Return ID, name, and type (built-in vs custom) for each perspective
4. **Comprehensive Listing**: Single method to access both built-in and custom perspectives
5. **Consistent Serialization**: Standardized format for perspective data across types

### Non-Functional Requirements
1. **Response Time**: Perspective listing completes within 300ms
2. **Data Consistency**: Accurate reflection of current perspective state
3. **Memory Efficiency**: Efficient handling of perspective metadata without loading full configurations
4. **Error Handling**: Graceful handling of perspective access errors

### Technical Requirements
1. **API Integration**: Use OmniFocus `Perspective.all` for comprehensive perspective access
2. **Type Distinction**: Clearly distinguish between built-in and custom perspective types
3. **Existing Patterns**: Follow established serialization patterns from other list methods
4. **Future Extensibility**: Structure to support future perspective management operations

## Implementation Plan

### Phase 1: API Research and Structure
1. **Perspective API Analysis**:
   - `Perspective.all` - returns all built-in and custom perspectives
   - `Perspective.BuiltIn.all` - built-in perspectives only
   - `Perspective.Custom.all` - custom perspectives only
   - Built-in perspectives: Flagged, Forecast, Inbox, Nearby, Projects, Review, Search, Tags

2. **Data Structure Design**:
   ```typescript
   interface PerspectiveInfo {
     id: string;
     name: string;
     type: 'built-in' | 'custom';
     builtin?: boolean; // for backwards compatibility
   }
   ```

### Phase 2: Plugin Implementation
1. **Method Implementation**:
   ```javascript
   lib.listPerspectives = params => {
     // 1. Access all perspectives using Perspective.all
     // 2. Iterate through perspectives and extract metadata
     // 3. Distinguish between built-in and custom types
     // 4. Return serialized perspective list
   };
   ```

2. **Perspective Processing**:
   - Iterate through `Perspective.all`
   - Extract `id` and `name` for each perspective
   - Determine type (built-in vs custom)
   - Create consistent serialization format

3. **Type Detection Logic**:
   - Check if perspective is instance of `Perspective.BuiltIn`
   - Check if perspective is instance of `Perspective.Custom`
   - Set appropriate type field in response

### Phase 3: Integration and Optimization
1. **Performance Considerations**:
   - Cache perspective list if performance becomes an issue
   - Efficient iteration through perspective collections
   - Minimal data extraction for listing operation

2. **Error Handling**:
   - Handle cases where perspectives might not be accessible
   - Graceful handling of perspective API changes
   - Clear error messages for perspective access failures

3. **Future Preparedness**:
   - Structure to support additional perspective metadata
   - Extension points for perspective management operations
   - Consistent patterns for other perspective methods
