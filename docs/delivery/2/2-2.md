# 2-2 Implement processInboxItem method

[Back to task list](./tasks.md)

## Description

Implement the `processInboxItem` method in the OmniFocus plugin (`omnifocus-mcp.omnijs`) to enable comprehensive inbox item processing through AI conversations. This method allows users to perform multiple operations on inbox items in a single call: assign to projects, add tags, rename, set notes, flag items, set duration, set dates, or delete items, effectively moving them out of the inbox into their proper organizational structure.

**Key Improvement**: Updated from action-based approach to flexible multi-operation interface for better UX and performance. Instead of requiring separate tool calls for "assign to project" and "add tags", users can now say "move this to Marketing project and tag it as urgent" in one operation.

This is a core workflow operation in OmniFocus - users capture ideas quickly in the inbox, then process them by deciding what project they belong to, when they should be done, and how they should be categorized.

## Requirements

### Functional Requirements
1. **Project Assignment**: Assign inbox items to existing projects with validation
2. **Tag Management**: Add tags to inbox items with validation
3. **Date Setting**: Set defer and due dates for inbox items
4. **Item Deletion**: Remove items from inbox (and database) when they're not needed
5. **Atomic Operations**: Each processing action succeeds or fails completely
6. **Post-Processing State**: Items are properly removed from inbox after processing

### Non-Functional Requirements
1. **Response Time**: Processing operations complete within 200ms
2. **Data Integrity**: All operations maintain OmniFocus database consistency
3. **Error Handling**: Clear error messages for invalid projects, tags, or dates
4. **Validation**: Comprehensive parameter validation before processing

### Technical Requirements
1. **Action Flexibility**: Support multiple action types in single method
2. **Existing Integration**: Leverage existing task update methods where possible
3. **Inbox Removal**: Ensure processed items are properly moved out of inbox
4. **Transaction Safety**: Atomic operations that don't leave partial state

## Implementation Plan

### Phase 1: Multi-Operation Framework
1. **Flexible Parameter Interface**:
   ```typescript
   interface ProcessInboxParams {
     taskId: string;
     projectId?: string;      // Move to project
     tagIds?: string[];       // Add tags
     name?: string;           // Rename task
     note?: string;           // Set note
     flagged?: boolean;       // Flag/unflag
     estimatedMinutes?: number; // Set duration
     deferDate?: string;      // Set defer date
     dueDate?: string;        // Set due date
     deleteTask?: boolean;    // Delete (exclusive)
   }
   ```

2. **Atomic Multi-Operation Structure**:
   ```javascript
   lib.processInboxItem = params => {
     // 1. Validate taskId and find inbox item
     // 2. Validate at least one operation specified
     // 3. Handle exclusive delete operation
     // 4. Execute all non-exclusive operations atomically
     // 5. Track operations performed for logging
     // 6. Return processed task or deletion confirmation
   };
   ```

### Phase 2: Operation Implementation
1. **Project Assignment** (moves out of inbox):
   - Use OmniFocus `moveTasks([task], project)` API
   - Validate projectId exists before moving

2. **Tag Management**:
   - Add multiple tags with duplicate prevention
   - Validate all tagIds exist before adding

3. **Task Property Updates**:
   - **name**: Rename task title
   - **note**: Set/update task notes
   - **flagged**: Set flagged status
   - **estimatedMinutes**: Set duration estimate

4. **Date Management**:
   - Set defer and/or due dates with validation
   - Accept ISO date string format

5. **Deletion** (mutually exclusive):
   - Use existing deleteObject() functionality
   - Return deletion confirmation instead of task data

### Phase 3: Enhanced Integration
1. **Operation Tracking**:
   - Log which operations were performed
   - Provide detailed timing information
   - Clear error messages for operation failures

2. **Atomic Execution**:
   - All operations succeed or all fail
   - Proper transaction-like behavior
   - Cache invalidation after mutations

3. **Improved UX**:
   - Single tool call for complex inbox processing
   - Natural language workflow: "move to project X and tag as urgent"
   - Reduced API round-trips for better performance
