## Requirements
- Structured logging with contextual metadata (job ID, execution ID, action types).
- Retry and backoff strategies for failed actions and scheduler disruptions.
- Catch-up logic to handle missed runs after downtime.
- Health and readiness endpoints (e.g., `/healthz`, `/readyz`) and optional Prometheus metrics.
- Alerting hooks (e.g., logging to Letta, message table) for repeated failures.
- Documentation describing monitoring setup and troubleshooting.

## Implementation Plan
1. Configure logging framework (structlog or standard logging with JSON formatter) integrated with FastAPI.
2. Implement retry decorators/backoff policies for external calls and job execution.
3. Add catch-up worker that inspects missed schedules on startup and decides rerun policy.
4. Create health/readiness endpoints and, if required, Prometheus metrics endpoint.
5. Integrate optional alerting via Letta or logs for failure thresholds.
6. Document observability configuration and recommended monitoring practices.
7. Add tests/simulations for downtime recovery and retry behavior.
