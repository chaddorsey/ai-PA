## Requirements
- Validate scheduler job lifecycle from creation to execution archive.
- Confirm MCP tool surface reflects scheduler data and errors gracefully.
- Demonstrate external action pipeline end-to-end (HTTP + script).
- Capture evidence (logs, screenshots, JSON responses) for review.

## Implementation Plan
1. **Prepare Test Data**
   - Define sample job payloads (morning reminder, webhook, script). 
   - Configure allow-listed script (mock ingestion) and HTTP echo endpoint (httpbin or local stub).
   - Ensure scheduler service and MCP server running via docker-compose (with mock SDK if available).

2. **Scenario A – Scheduler REST Lifecycle**
   - Create job via REST (`POST /v1/jobs`).
   - Trigger immediate execution (`POST /v1/jobs/{id}/trigger`).
   - Verify execution record (`GET /v1/jobs/{id}/executions`).
   - Confirm metrics endpoint increments counters.

3. **Scenario B – MCP Tool Integration**
   - Using MCP client (Letta or CLI), list jobs (`scheduler_list_jobs`).
   - Retrieve job details via MCP and ensure outputs mirror REST response.
   - Update and delete job via MCP tools; verify REST reflects changes.
   - Capture request/response logs.

4. **Scenario C – External Action End-to-End**
   - Schedule job with HTTP action pointing to echo endpoint; verify execution output persisted.
   - Schedule job with allow-listed script; confirm stdout/return code stored.
   - Validate metrics counters for success/failure paths.

5. **Scenario D – Resilience & Observability**
   - Simulate scheduler downtime (stop service) and restart; ensure catch-up logging and metrics consistent.
   - Check structured logs for job/execution context (spot-check log lines).

6. **Documentation & Evidence**
   - Record curl commands, MCP invocations, and log excerpts.
   - Summarize findings in implementation notes; attach evidence to repository (`docs/delivery/19/evidence/` folder).
