# [1-19] Fix task projectID null issue using containingProject

[Back to task list](./tasks.md)

## Description

Fix the issue where tasks are returning `projectID: null` even when they are part of a project in OmniFocus. The problem is in the `serializeTask` function which uses `t.project` (only returns a value for root project tasks) instead of `t.containingProject` (returns the containing project for all tasks except inbox items).

## Requirements

### Root Cause Analysis
- The current `serializeTask` function uses `t.project` which only returns a value for tasks that are root tasks of projects
- According to OmniFocus API documentation:
  - `t.project`: "The `Project` that this `Task` is the root task of, or `null` if this task is in the inbox or contained by another task"  
  - `t.containingProject`: "The `Project` that this `Task` is contained in, either as the root of the project or indirectly from a parent task. If this task is in the inbox, then this will be `null`"

### Fix Requirements
1. **Replace project reference**: Change `t.project` to `t.containingProject` in `serializeTask` function
2. **Update exclusion logic**: Update all project exclusion logic to use `containingProject` consistently
3. **Maintain backward compatibility**: Ensure the fix doesn't break existing functionality
4. **Test coverage**: Verify the fix works for all task types:
   - Regular tasks within projects
   - Root project tasks
   - Sub-tasks and task groups
   - Inbox items (should remain null)

## Implementation Plan

### Step 1: Update serializeTask Function
```javascript
function serializeTask(t) {
  return {
    id:        bareId(t.id),
    name:      t.name,
    note:      t.note,
    flagged:   t.flagged,
    deferDate: t.deferDate ? t.deferDate.toISOString() : null,
    dueDate:   t.dueDate   ? t.dueDate.toISOString()   : null,
    duration:  t.estimatedMinutes,
    projectId: t.containingProject ? bareId(t.containingProject.id) : null,  // Changed from t.project
    folderId:  (t.containingProject && t.containingProject.folder)
              ? bareId(t.containingProject.folder.id)
              : null,
    contexts:  t.tags.map(x => bareId(x.id)),
    completed: t.completed,
    dropped:   !t.effectiveActive
  };
}
```

### Step 2: Update Exclusion Logic Consistency
- Update `queryTasks` project exclusion check to use `containingProject`
- Update `searchTasks` project exclusion check to use `containingProject`  
- Update folder hierarchy exclusion to use `containingProject`

### Step 3: Test All Task Types
- Test with regular project tasks
- Test with root project tasks
- Test with nested sub-tasks
- Test with inbox items
- Verify exclusion filters still work correctly
