## Description

Implement robust error handling throughout the OmniFocus plugin (`omnifocus-mcp.omnijs`) for all query operations, ensuring graceful failure handling and clear error messages suitable for AI interpretation. This includes handling invalid IDs, parameter validation, OmniFocus availability issues, and edge cases discovered during implementation.

The error handling system will provide consistent, actionable error messages that both end users and AI assistants can understand and act upon, improving the overall reliability and user experience of the MCP bridge.

## Requirements

### Functional Requirements
1. **Parameter Validation**: Validate all input parameters with clear error messages
2. **ID Validation**: Handle invalid task, project, and tag IDs gracefully
3. **Date Validation**: Validate date formats and ranges in query parameters
4. **OmniFocus Availability**: Handle OmniFocus unavailability and database issues
5. **Error Message Consistency**: Standardized error format across all methods

### Non-Functional Requirements
1. **Error Clarity**: Error messages suitable for both AI and human understanding
2. **Performance**: Error handling adds minimal overhead to successful operations
3. **Logging**: Appropriate error logging for debugging without exposing sensitive data
4. **Recovery**: Graceful degradation when possible

### Technical Requirements
1. **Exception Handling**: Comprehensive try-catch blocks around OmniFocus API calls
2. **Error Categorization**: Distinguish between user errors, system errors, and data errors
3. **Error Propagation**: Proper error propagation through the bridge layer
4. **Validation Utilities**: Reusable validation functions for common parameter types

## Implementation Plan

### Phase 1: Core Error Handling Infrastructure
1. **Error types definition**:
   ```javascript
   const ErrorTypes = {
     INVALID_PARAMETER: 'invalid_parameter',
     NOT_FOUND: 'not_found',
     OMNIFOCUS_UNAVAILABLE: 'omnifocus_unavailable',
     INVALID_DATE: 'invalid_date',
     SYSTEM_ERROR: 'system_error'
   };
   ```

2. **Error formatting utility**:
   ```javascript
   function createError(type, message, details = {}) {
     return { error: type, message, details };
   }
   ```

3. **Parameter validation utilities**: Reusable functions for ID, date, and range validation

### Phase 2: Method-Specific Error Handling
1. **listTasksByTag error handling**:
   - Invalid tag ID validation
   - Project ID validation (when provided)
   - Boolean parameter validation

2. **queryTasks error handling**:
   - Date format validation
   - Duration range validation
   - Conflicting parameter detection

3. **OmniFocus API error handling**:
   - Database access failures
   - Null reference handling
   - Timeout scenarios

### Phase 3: Integration and Testing
1. **Error propagation testing**: Verify errors reach bridge and server layers correctly
2. **Error message review**: Ensure AI can interpret and communicate errors to users
3. **Edge case discovery**: Test boundary conditions and unusual parameter combinations

## Verification

### Test Plan

   - Test conflicting parameter combinations

2. **System Error Testing**:
   - Test with OmniFocus closed or unavailable
   - Test with database corruption scenarios
   - Test memory pressure and resource exhaustion

3. **Error Message Quality Testing**:
   - Review error messages for clarity and actionability
   - Test AI interpretation of error messages
   - Verify error details provide sufficient troubleshooting information

4. **Recovery Testing**:
   - Test graceful degradation when partial data is available
   - Test recovery after temporary OmniFocus unavailability
   - Test error handling during partial query completion

### Success Criteria
- All invalid parameters produce clear, actionable error messages
- System errors are caught and reported gracefully without crashes
- Error messages are suitable for AI interpretation and user communication
- Error handling adds < 5ms overhead to successful operations
- Recovery mechanisms work correctly after temporary failures
