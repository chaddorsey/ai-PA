# 21-3 ASP encoding (grid, hard constraints)

## Description
Write the clingo logic program for selecting one start slot per request, occupying D slots, no overlaps, windows, work hours, min gaps.

## Requirements
- Define predicates: `slot/1`, `busy/2`, `needs/2`, `window/2`, `duration/2`, `workhours/2`
- Hard constraints:
  - `:- occurs(Q,T), needs(Q,P), busy(P,T).` (no overlaps)
  - `:- start(Q,T), not window(Q,T).` (must be in allowed window)
  - `:- occurs(Q,T), needs(Q,P), not within_workhours(P,T).` (respect work hours)
  - `:- start(Q,T1), occurs(Q,T2), T2 < T1 + min_gap.` (minimum gap after previous events)
- Generate facts from normalized event data and scheduling problem
- Ensure encoding is sound and complete for constraint satisfaction

## Implementation Plan
1. Define base ASP program structure:
   - Facts section: slot definitions, busy slots, work hours, scheduling request parameters
   - Rules section: choice rules for selecting start slots, constraint rules for hard requirements
2. Implement predicate definitions:
   - `slot(S).` - All available time slots in the grid
   - `busy(P, S).` - Participant P is busy at slot S
   - `needs(Q, P).` - Request Q requires participant P
   - `window(Q, S).` - Request Q is allowed to start at slot S (from time window preference)
   - `duration(Q, D).` - Request Q requires D slots (duration in 15-min units)
   - `workhours(P, S).` - Participant P is available during work hours at slot S
3. Write constraint rules:
   - No double-booking: meeting cannot occur when any participant is busy
   - Time window: meeting must start within allowed window
   - Work hours: meeting must occur during participant work hours
   - Minimum gaps: enforce minimum gap between meetings
   - Duration: meeting must occupy exactly D consecutive slots
4. Generate facts programmatically:
   - Convert normalized slot data to ASP facts format
   - Generate facts for each scheduling request
   - Include context-derived constraints (locked events, min gaps)
