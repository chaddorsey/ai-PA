## Requirements
- Set timeouts and memory limits for clingo solver
- Handle LLM API keys via Letta tool configuration (environment variables)
- Document allowed horizon sizes and performance characteristics
- Add dependency installation to `letta/requirements.txt` (dspy-ai, clingo)
- Document security considerations and best practices

## Implementation Plan
1. Configure timeouts:
   - Set clingo solve timeout (default: 30 seconds, configurable)
   - Set DSPy extraction timeout (default: 10 seconds)
   - Set overall tool timeout (default: 60 seconds)
   - Make timeouts configurable via environment variables
2. Set memory limits:
   - Monitor memory usage during ASP solving
   - Limit horizon size to prevent excessive memory (max 4 weeks, max 10 participants)
   - Document memory requirements for different horizon sizes
3. Handle LLM API keys:
   - DSPy requires LLM API keys (OpenAI, Anthropic, etc.)
   - Read from Letta tool environment variables (e.g., `OPENAI_API_KEY`)
   - Document required environment variables
   - Provide clear error messages if keys are missing
4. Add dependencies:
   - Add `dspy-ai` to `letta/requirements.txt`
   - Add `clingo` to `letta/requirements.txt`
   - Document these as shared dependencies for future tools
   - Test installation in Letta container
5. Document configuration:
   - Create configuration guide with all settings
   - Document allowed horizon sizes (recommended: 1-4 weeks)
   - Document participant limits (recommended: <10 for performance)
   - Document performance characteristics (typical solve times)
6. Security considerations:
   - Document that tool does not write to calendars (read-only on events)
   - Document that tool does not expose sensitive data in logs (PII redaction)
   - Document that tool runs in Letta's sandboxed environment
   - Note that LLM API keys must be kept secure
