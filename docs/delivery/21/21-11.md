## Requirements
- Add structured logging for tool invocations
- Log inputs (with PII redaction), objective values, proposals, explanations
- Integrate with Letta's logging infrastructure
- Support configurable log levels and PII redaction settings

## Implementation Plan
1. Define logging structure:
   - Use Python `logging` module with structured format (JSON or key-value pairs)
   - Log at INFO level for normal operations, DEBUG for detailed traces
   - Include correlation IDs for tracing requests
2. Log tool invocations:
   - Input parameters (utterance, participant count, event count, context summary)
   - Redact PII: participant emails, event titles (optional), personal notes
   - Log timing: extraction time, normalization time, solve time, total time
3. Log optimization results:
   - Objective scores (moved minutes, focus block bonus, preference penalty)
   - Selected proposal details (start time, participants, moved events count)
   - ASP statistics (solve time, models found, optimization level)
4. Log explanations:
   - Store generated explanation text
   - Log which factors influenced the decision
5. Handle errors:
   - Log error type, message, stack trace (at ERROR level)
   - Log UNSAT cases with blocking constraints
   - Log timeout cases with partial results
6. Configure PII redaction:
   - Support environment variable or config file for redaction settings
   - Default: redact participant emails, keep event titles
   - Option to redact event titles, personal notes, etc.
7. Integrate with Letta logging:
   - Use Letta's logging configuration if available
   - Or configure separate logger for scheduling tool
   - Ensure logs are accessible for debugging

## Verification
- Logs are generated for all tool invocations
- PII is properly redacted according to configuration
- Logs include all required information (inputs, outputs, timing, errors)
- Logs are readable and structured for analysis
- Error cases are logged with sufficient detail
