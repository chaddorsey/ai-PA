## Requirements
- Accept only expanded instances (Get_Events should return expanded events between from/to).
- Handle time‑zones by converting to UTC; retain participant TZ for display.
- Output: `busy(person, slot)`, `work_hours(person, ...)`, `locked/protected/flexible` flags.
- Build slot indexer with 15-minute granularity starting from horizon_start_utc.
- Compute minimum gap buffers around events based on context policy.

## Implementation Plan
1. Build a slot indexer:
   - `slot0 = horizon_start_utc`, step=15 minutes
   - Create mapping from UTC datetime to slot index
   - Support horizon_end_utc for bounded planning window
2. For each event in `events_by_participant`:
   - Convert start/end to UTC using participant timezone
   - Mark all occupied slots (inclusive of event start, exclusive of event end)
   - Compute min gap buffers before/after event based on `context_json.policy.hard.min_gap_min`
   - Tag event protection level: `locked` (hard constraint), `protected` (soft preference), `flexible` (can be moved)
3. Extract work hours from context_json:
   - Parse `work_hours` per participant (e.g., "M-F 09:00-17:30")
   - Convert to UTC slot ranges
   - Generate `workhours(person, slot)` facts for valid working time slots
4. Handle edge cases:
   - Events crossing DST boundaries (preserve UTC conversion)
   - All-day events (optional: treat as working-hours blocks or exclude from grid)
   - Events with missing timezone (default to UTC or context default)
