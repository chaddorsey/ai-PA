# 21-13 Replace ASP/clingo with pure Python constraint solver

[Back to task list](./tasks.md)

## Description

Replace the ASP/clingo-based optimization backend with a pure Python constraint checking and ranking system. This addresses the "too many messages" grounding errors by eliminating clingo entirely for the common case (finding free slots and single-meeting moves). The solution will use existing free slot pre-filtering, implement Python-based constraint checking and ranking, and maintain the same tool interface for drop-in compatibility.

## Requirements

1. **Maintain existing interface**: The `orchestrate_scheduling` function signature and response format must remain unchanged to ensure compatibility with existing Letta agent integrations.

2. **Use existing infrastructure**:
   - Leverage `_find_free_slots()` from `fact_generator.py` for pre-filtering
   - Use existing `normalize_events()` for 15-minute grid conversion
   - Keep DSPy extraction (`extract_with_fallback`) for natural language processing
   - Maintain existing schemas and response formats

3. **Implement Python constraint checking**:
   - Check all participants are free for meeting duration
   - Verify work hours constraints
   - Respect time window boundaries
   - Check min_gap after busy slots
   - Respect locked events (cannot overlap)

4. **Implement ranking/scoring system**:
   - Score slots by preferences (minimize disruption, maximize focus blocks, respect timing preferences)
   - Use weighted scoring (can be refined to lexicographic later if needed)
   - Return top N proposals (default: 1, configurable)

5. **Handle single-meeting moves**:
   - If no free slots, identify flexible meetings that can be moved
   - For each flexible meeting, compute potential slots if moved
   - Score candidates including move cost
   - Return best option with move details

6. **Preserve ASP option for future**:
   - Keep ASP code in place but disabled/optional
   - Add flag to enable ASP for complex multi-meeting re-scheduling (future enhancement)
   - Document when ASP would be valuable vs. Python

7. **Error handling**:
   - Return `unsat` status when no feasible solutions found
   - Provide clear explanations and relaxation suggestions
   - Maintain existing debug info structure (adapt as needed)

## Implementation Plan

### Phase 1: Core Python Solver

1. **Create `python_solver.py` module**:
   ```python
   def find_optimal_slot(
       free_slots: Set[int],
       normalized_data: Dict[str, Any],
       scheduling_problem: SchedulingProblem,
       slot_indexer: SlotIndexer
   ) -> Optional[Dict[str, Any]]:
       """Find optimal slot from free slots using Python ranking."""
   ```

2. **Implement constraint checking functions**:
   - `check_work_hours(slot, participants, work_hours_slots) -> bool`
   - `check_time_window(slot, time_window_start, time_window_end, slot_indexer) -> bool`
   - `check_min_gap(slot, busy_slots, min_gap_slots, participants) -> bool`
   - `check_locked_events(slot, locked_events, participants, duration_slots) -> bool`

3. **Implement scoring/ranking**:
   - `compute_disruption_score(slot, busy_slots, flexible_events, participants, duration_slots) -> float`
   - `compute_focus_block_bonus(slot, busy_slots, participants, duration_slots) -> float`
   - `compute_preference_score(slot, preferred_times, preferred_days, slot_indexer) -> float`
   - `rank_slots(free_slots, scores) -> List[Tuple[float, int]]`

### Phase 2: Single-Meeting Move Support

4. **Implement move candidate generation**:

5. **Move cost calculation**:
   - Compute shift distance for moved meeting
   - Penalize moves of protected events more than flexible events

## Open Questions

1. Should we keep ASP code as optional fallback, or remove entirely?
   - **Recommendation**: Keep as optional, disabled by default, for future complex multi-meeting re-scheduling

2. How many proposals should we return by default?
   - **Recommendation**: 1 (current behavior), but make configurable

3. Should scoring be weighted sum or lexicographic?
   - **Recommendation**: Start with weighted sum (simpler), can add lexicographic later if needed

4. How to handle complex multi-meeting moves?
   - **Recommendation**: Return `unsat` with suggestion to relax constraints, or enable ASP for these cases (future enhancement)
