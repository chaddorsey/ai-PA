# 21-4 ASP soft constraints & lexicographic objectives

## Description
Add weak constraints with levels (lexicographic): L1 Protect protected events; L2 minimize total moved minutes; L3 maximize focus blocks; L3 respect participant preferences.

## Requirements
- Use `#minimize [...] @level` syntax for lexicographic optimization
- Level order: feasibility (implicit) < 1 protect < 2 move cost < 3 focus/prefs
- L1: Minimize violations of protected event boundaries (prefer not moving protected events)
- L2: Minimize total minutes that existing events must be moved
- L3: Maximize long focus blocks (consecutive free slots) created by the schedule
- L3: Minimize preference violations (e.g., preferred times, participant preferences)
- Ensure optimization levels are properly ordered and weighted

## Implementation Plan
1. Define weak constraint structure:
   - Use clingo's `#minimize` directive with level annotations
   - Each level optimizes a different objective in lexicographic order
2. Implement L1 (Protect protected events):
   - Detect when a proposal would require moving a protected event
   - Penalize such moves: `#minimize { 1@1 : moved_protected(E) }.`
   - Protected events identified from context_json policy
3. Implement L2 (Minimize moved minutes):
   - Calculate total minutes that existing events must shift
   - Penalize based on shift amount: `#minimize { M@2 : moved_minutes(M) }.`
   - Weight by event importance if available
4. Implement L3 (Maximize focus blocks):
   - Identify consecutive free slots (focus blocks) created by the schedule
   - Reward longer blocks: `#minimize { -BlockLength@3 : focus_block(BlockLength) }.`
   - Only count blocks above minimum threshold (e.g., 90 minutes)
5. Implement L3 (Respect preferences):
   - Penalize deviations from preferred times, days, or participant preferences
   - Weight by preference strength: `#minimize { Penalty@3 : preference_violation(Penalty) }.`
6. Test optimization behavior:
   - Verify lexicographic ordering (L1 optimized first, then L2, then L3)
   - Test scenarios where trade-offs occur between objectives

## Verification
- Scenario shows a 30-minute shift that creates a 120-minute focus block is preferred when move cost is low relative to block bonus
- Lexicographic ordering correctly prioritizes L1 > L2 > L3
- Optimization produces expected results for test cases
- Weak constraints are syntactically correct and clingo can optimize
