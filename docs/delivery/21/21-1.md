## Requirements
- **Inputs**: `utterance` (str), `events_by_participant` (dict), `context_json` (dict|None).
- **Outputs**: `status` (ok/unsat/bad_input), `proposals[]` (list of Proposal objects), `explanation` (str), optional `relaxations[]` (on UNSAT), `debug` (dict).
- All fields documented with type hints and descriptions; schema renders correctly in Letta ADE/SDK.
- Pydantic models must support JSON serialization for Letta tool schema generation.

## Implementation Plan
1. Draft Pydantic models:
   - `Event`: Represents a calendar event with id, title, start, end, locked/protected/flexible flags
   - `SchedulingProblem`: Encodes the scheduling request (participants, duration, time window, preferences)
   - `Proposal`: A proposed meeting slot with start/end times, participants, moved events, objective scores
   - `MovedEvent`: Details about an event that needs to be moved to accommodate the proposal
   - `ObjectiveScores`: Breakdown of optimization objective values (moved minutes, focus block bonus, preference penalty)
   - `ResponseEnvelope`: Complete tool response with status, proposals, explanation, relaxations, debug info
2. Write the function stub with comprehensive docstring (Letta auto-schema generation):
   ```python
   def orchestrate_scheduling(
       utterance: str,
       events_by_participant: Dict[str, List[Event]],
       context_json: Optional[Dict[str, Any]] = None
   ) -> ResponseEnvelope:
       """Orchestrate scheduling by finding optimal meeting times..."""
   ```
3. Provide example payloads for integration tests:
   - Sample `events_by_participant` structure
   - Sample `context_json` with working hours, preferences, policy rules
   - Expected response structure for successful and UNSAT cases
