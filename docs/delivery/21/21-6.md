## Requirements
- Extract structured scheduling problem from natural language utterance
- Use DSPy `Predict` or `ChainOfThought` for initial extraction
- Apply `BestOfN/Refine` with JSON schema validator for reliability
- Target ≥95% schema-valid outputs on dev set
- Handle edge-case utterances correctly (ambiguous requests, missing information)

## Implementation Plan
1. Define DSPy signature:
   - Input: `utterance` (str), `context_json` (dict with existing rules/preferences)
   - Output: `problem_delta_json` (dict matching SchedulingProblem schema)
   - Signature should include examples and constraints
2. Implement base extraction module:
   - Use `dspy.Predict` or `dspy.ChainOfThought` for initial extraction
   - Provide few-shot examples of good extractions
   - Include context_json in prompt for rule-aware extraction
3. Add reliability layer:
   - Wrap base module with `dspy.BestOfN` (try N=3-5 candidates)
   - Apply JSON schema validator to each candidate
   - Select best valid candidate (or refine if none valid)
4. Implement refinement:
   - If no valid candidates, use `dspy.Refine` to fix schema violations
   - Provide feedback about what's wrong with invalid outputs
   - Iterate until valid or max attempts reached
5. Handle edge cases:
   - Ambiguous participant names (resolve against context)
   - Missing duration (infer from utterance or use default)
   - Vague time windows (expand to reasonable defaults)
   - Conflicting preferences (prioritize based on context rules)
6. Create dev set:
   - 20+ example utterances covering common patterns
   - Include edge cases and ambiguous requests
   - Validate extraction accuracy and schema compliance

## Verification
