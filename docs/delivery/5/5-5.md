### Baseline Observations (2025-10-16)

- `message_im_hybrid.py` posts an initial `chat_postMessage` with literal `"..."`, then repeatedly calls `chat_update` every ~300 ms as artificial chunks arrive, so no native typing indicator is shown.
- `LettaAPIStreaming.chat_stream` buffers the entire SSE response into `full_content`, then replays it in fixed 3-word chunks with a 100 ms delay; this simulates streaming but prevents us from reacting to token-level events (all tokens arrive at once before the loop begins).
- Because the SSE payload is consumed before chunking, Slack never receives actual typing metadata or paced updates tied to the upstream stream; improving this will require listening to token events as they arrive and driving `chat_sendTyping` in parallel.
- Slash command handlers like `ask_bolty_streaming.py` also collect all chunks before replying, reinforcing that our current implementation treats streaming as a post-processed simulation rather than true token-by-token relay.

### Design Notes (2025-10-16)

1. **Slack Streaming API Adoption**
   - Use the official `WebClient.chat_stream` interface (backed by `chat.startStream`, `chat.appendStream`, `chat.stopStream`) to manage in-progress messages so Slack renders typing indicators without manual dot animations.
   - Start streams from the initial DM reply message returned by `chat_postMessage`, supplying its `ts` as the `thread_ts` for downstream appends.
2. **Letta Delta Propagation**
   - Parse each SSE event from Letta in `LettaAPIStreaming` and yield meaningful deltas (text, rich segments) immediately; avoid the current word-based chunking shim.
   - Accumulate content in a buffer for final message assembly while still streaming intermediate chunks.
3. **Backpressure & Error Handling**
   - Lean on Slack SDK buffering (`buffer_size` default 256) to stay under rate limits; log when buffer flushes occur or when `chat_appendStream` raises rate-limit errors.
   - Implement a watchdog timer; if no Letta chunk arrives within a grace period, close the stream, send a fallback message, and mark telemetry for follow-up.
4. **Configuration & Scopes**
   - Confirm workspace has required scopes (`chat:write`, `chat:write.public`, streaming beta) and surface a boolean environment flag to toggle streaming behaviour.
   - Use `assistant.threads.setStatus` to surface Slack-native typing/loading messages during streaming and clear them when responses finish.
   - Document flag usage, scope requirements, and assistant status behaviour in the Verification section and PBI documentation.
