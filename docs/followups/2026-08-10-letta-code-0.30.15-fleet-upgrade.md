# Follow-up: upgrade the local-mode fleet from letta-code 0.28.18 → 0.30.15

**Decision as of 2026-08-10:** stay on **0.28.18** for now (just recovered from a
broken 0.27.27→0.28.18 self-upgrade — see below). Upgrade to **0.30.15** later,
canary-first, once the headless-validation checks pass.

## Current state
- All local-mode agents run global npm `@letta-ai/letta-code`.
- MC / kinara is on **0.28.18** (reinstalled cleanly 2026-08-10 after the symlink broke).
- Latest published is **0.30.15** (32 releases ahead: two minor bumps, 0.29.x + 0.30.x).

## Why upgrade (what we gain)
- **Local backend:** OpenAI-compatible provider wired into the local backend (0.30.6);
  hot-reload agent records from disk (0.30.15); cron falls back to local schedule when
  Cloud is unavailable (0.30.6).
- **Reliability / anti-stall** (relevant to the #99 silent-stall history): abort wedged
  HTTP read after terminal SSE + force-kill timed-out process trees (0.30.9); stream
  reconnection recovery (0.30.0); re-present recovered AskUserQuestion approvals after
  restart (0.30.12).
- **Slack / multi-channel:** per-channel mention gating (0.30.6); conversation tags
  replace source prefixes (0.30.9); shared reaction ingress policy (0.30.14).
- **Worktrees & monitors:** `ExitWorktree` tool (0.30.14); event monitors / Monitor
  tool (0.30.14–15).
- **CLI:** BYOK OpenAI reasoning controls + responsive markdown tables (0.29.0).

## Why it's low-risk for the statusline mod
Neither 0.29.0 nor 0.30.0 documents any breaking change to **mods / `ui.openPanel` /
statusline / extensions / local backend**. The mods API only gained surface area
(0.30.6 "Expose agent MemFS to mod callbacks"; 0.30.12 desktop notifications). The mod
(`~/.letta/mods/statusline.tsx`) lives OUTSIDE the npm package, so a version bump won't
overwrite it. See `reference/workflows/letta_code_statusline_mod.md` in MC's memfs.

## The one real watch item — stricter validation (could bite automation, not the TUI)
- **0.30.0** — rejects implicit headless positional prompts.
- **0.30.15** — validates API keys against the supplied base URL.

Before rolling the fleet, verify all **headless / scripted `letta` invocations** still
parse and the local backend's base-URL/key pairing passes the new check:
- cron-driven briefings (schedule / daily-briefing generators)
- analytics pipeline stages (`scripts/run-analytics-stage.sh`)
- any non-interactive `letta ... <<prompt` or `--print`/headless calls in `~/bin/letta-*`
  wrappers or launchd jobs

## Upgrade procedure (per agent — npm global)
npm refuses to overwrite an existing (even dangling) bin symlink, so clear it first:

```bash
rm -f /opt/homebrew/bin/letta
npm install -g @letta-ai/letta-code@0.30.15
# verify NOT dangling + correct version:
readlink -f /opt/homebrew/bin/letta && letta --version
```

Then restart the supervised pane from a shell NOT parented by the letta TUI. If the
supervisor is at its crash prompt, send a **literal newline** (`tmux send-keys -t kinara C-j`),
not Enter — a `-9`'d TUI leaves the pty in raw mode so `\r` never reaches the `read`.

## Rollout plan
1. **Canary kinara (MC) first.** Upgrade, restart, then confirm:
   - [ ] statusline panel still renders (next meeting + availability in the footer)
   - [ ] interactive tool calls work (approval cycle intact)
   - [ ] headless/scripted calls the fleet depends on still parse (see watch item)
   - [ ] local backend base-URL/key check passes
2. Soak ~1 day on kinara.
3. Roll the other five (email, docs, calendar, pulse, tasks) with the same command.
4. If anything regresses, roll back that agent: `rm -f /opt/homebrew/bin/letta &&
   npm i -g @letta-ai/letta-code@0.28.18`.

## Root-cause reminder (don't repeat the 2026-08-10 break)
The break was a symlink pointed at npm's **transient staging dir**
(`.letta-code-<hash>/letta.js`), which npm deletes post-install → dangling → no `letta`.
**Never hand-create the symlink or target a staging path** — a clean `npm i -g`
recreates a stable symlink to `../lib/node_modules/@letta-ai/letta-code/letta.js`.
Full post-mortem in `reference/workflows/letta_code_statusline_mod.md` (MC memfs).
