# Archiving Task Source References in Archival Memory

When you extract a task from any source, the `add_extracted_tasks` tool handles both task extraction and archival source referencing in a single atomic call. It adds the task to the `extracted_tasks` memory block and inserts a structured source reference passage into archival memory, linked by `ref_id`.

## Workflow

Call `add_extracted_tasks` with all source metadata. The tool:

1. Generates a `ref_id` (8-char hex)
2. Appends `[extracted_time: YYYY-MM-DD HH:MM; ref_id: XXXXXXXX] task_description` to the `extracted_tasks` block
3. Formats and inserts the archival source reference passage
4. Returns `{status, ref_id, archival_passage_id}`

**Do NOT call `archival_memory_insert` separately** — the tool handles it.

## Tool Call Format

```
add_extracted_tasks(
  task_description="Review agenda items highlighted in yellow on worksheet",
  source_type="slack",
  source_context="Direct message from Danielle Kehoe",
  reference_id="slack-D09DLK9KRB4-1769606904.463859",
  source_text="the items highlighted in yellow on the worksheet are my agenda items...",
  from_person="Danielle Kehoe (U09B5JUK2TY)",
  location="directmessage",
  location_id="D09DLK9KRB4",
  source_timestamp="2026-02-11T06:37:00Z",
  project="grants"  # optional
)
```

## Parameters

| Parameter | Required | Description |
|-----------|----------|-------------|
| `task_description` | yes | Concise verb-led task title |
| `source_type` | yes | `"slack"`, `"google-docs"`, `"meeting"`, `"email"` |
| `source_context` | yes | Human-readable origin (e.g., "Direct message from Danielle Kehoe") |
| `reference_id` | yes | Deterministic canonical ID (see formats below) |
| `source_text` | yes | Verbatim source text — never summarize |
| `from_person` | yes | Person name or ID who originated the task |
| `location` | yes | Channel name, document URL, meeting title, or subject line |
| `location_id` | yes | Machine-readable location identifier |
| `source_timestamp` | yes | ISO 8601 timestamp of the source (e.g., "2026-02-11T06:37:00Z") |
| `project` | no | Project name for tagging (adds 4th tag: `project:{name}`) |

## Source Types and Reference ID Formats

| Type shorthand | Use for | Reference ID format | Location field |
|---|---|---|---|
| `slack` | DMs, channels, MPDMs | `slack-{channel_id}-{ts}` | Channel name or "directmessage" |
| `google-docs` | Docs, Sheets, Slides | `gdocs-{document_id}` | Full document URL |
| `meeting` | Granola, calendar meetings | `meeting-{meeting_id}` | Meeting title |
| `email` | Gmail, other email | `email-{message_id}` | Subject line |

## Archival Passage Format (generated by tool)

The tool automatically generates this passage and inserts it into archival memory:

```
TASK: [task_description]
REF_ID: [8-char hex]

SOURCE REFERENCE
- Type: [source_type]
- Context: [source_context]
- Reference ID: [reference_id]

SOURCE METADATA
- Timestamp: [source_timestamp]
- From: [from_person]
- Location: [location]
- Location ID: [location_id]

TIMESTAMPS
- Source: [source_timestamp]
- Extracted: [auto-generated ISO timestamp]
- OmniFocus: pending

OMNIFOCUS
- Task ID: pending
- Status: extracted

SOURCE TEXT
[source_text]
```

## Tag Formula (exactly 3-4 tags, auto-generated)

1. **Source type** (required): `source:slack`, `source:google-docs`, `source:meeting`, `source:email`
2. **Temporal** (required): `YYYY-MM` from extraction timestamp (e.g. `2026-02`)
3. **Status** (required): `status:extracted`
4. **Project** (optional): `project:{name}` — only if `project` parameter is provided

## Task Lifecycle Tools

After extraction, tasks move through a lifecycle managed by three additional tools.

### Status Vocabulary

| Status | Meaning | Tag |
|--------|---------|-----|
| `extracted` | Newly captured, pending review | `status:extracted` |
| `confirmed` | Accepted and sent to OmniFocus | `status:confirmed` |
| `completed` | OmniFocus task finished | `status:completed` |
| `rejected` | Not a real task, discarded | `status:rejected` |
| `merged` | Consumed into a merged task | `status:merged` |

### update_extracted_task

Update content of an existing task without changing its status. Use when new information emerges.

```
update_extracted_task(
  ref_id="a1b2c3d4",
  task_description="Updated task title",     # optional
  source_context="Updated context",          # optional
  source_text="Additional verbatim text"     # optional, replaces existing
)
```

- Only provided fields are changed; all others preserved
- Adds `- Updated: [timestamp]` to TIMESTAMPS section
- Updates both the archival passage and the extracted_tasks block entry (if title changed)

### transition_extracted_task

Change the status of a task. Removes the task from the `extracted_tasks` block.

```
# Confirm — send to OmniFocus (requires omnifocus_task_id)
transition_extracted_task(ref_id="a1b2c3d4", action="confirm", omnifocus_task_id="oFxyz123")

# Reject — not a real task
transition_extracted_task(ref_id="a1b2c3d4", action="reject")

# Complete — OmniFocus task finished
transition_extracted_task(ref_id="a1b2c3d4", action="complete")
```

**confirm**: Sets `- OmniFocus created: [timestamp]`, populates Task ID, changes Status to `confirmed`.

**reject**: Prefixes TASK with `[REJECTED]`, removes OMNIFOCUS section, adds `- Rejected: [timestamp]`.

**complete**: Prefixes TASK with `[COMPLETED]`, adds `- Completed: [timestamp]`, changes Status to `completed`.

### merge_extracted_tasks

Combine multiple related tasks into a single new task.

```
merge_extracted_tasks(
  ref_ids="a1b2c3d4,e5f6a7b8",
  merged_task_description="Combined task covering both originals",
  project="grants"  # optional
)
```

- Creates a new passage with `MERGED_IDS: a1b2c3d4, e5f6a7b8`
- Marks each original passage as `[MERGED]` with `MERGE_PARENT_ID: [new_ref_id]`
- The merged task becomes the active record for subsequent confirm/complete transitions
- Original passages retain full source data, reachable via MERGED_IDS

### Cross-Agent Operations

All lifecycle tools accept an optional `agent_id` parameter to operate on a different agent's archival memory. If omitted, defaults to the calling agent.

## Rules

- **source_text** is always verbatim. Do not summarize or paraphrase.
- **reference_id** must be deterministic — the same source always produces the same ID.
- **source_timestamp** must be ISO 8601 format.
- **Status** reflects the current state at time of archival. Lifecycle tools handle passage updates automatically (delete and re-insert).
- If a field is not yet known (e.g. OmniFocus ID before sending), the tool uses `"pending"`.
- The passage is **self-contained** — readable without any other context.
- **ref_id** links the extracted task entry in core memory to the archival passage.
- Tasks are **removed from the extracted_tasks block** when they transition out of `extracted` status. The block is a working queue; archival memory is the durable history.

## Key Principles

- Single tool call — no separate archival_memory_insert needed
- All data fields go IN the passage text (not tags)
- Only 3-4 tags for filtering/retrieval
- Consistent structure — same format every time
- Reference IDs are deterministic — same source = same ID
- Lifecycle tools handle all passage mutations — agents never edit archival text directly
