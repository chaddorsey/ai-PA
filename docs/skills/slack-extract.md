# Slack Analytics Extract CLI Skill

## When to use

- **Fire-and-forget CSV export trigger**: `slack-extract trigger
  channels`. Clicks "Export CSV" in the Slack admin UI, then exits.
  The CSV is generated by Slack server-side and appears in your
  Slack workspace's Files area within a few minutes. Cheapest option;
  no local download.
- **Full download flow**: `slack-extract download channels --dir
  /tmp/csvs`. Trigger + wait + download to a local directory. Use
  when the agent needs the CSV bytes immediately for analysis.
- **Date-ranged export**: `slack-extract dated channels --start
  2026-05-01 --end 2026-05-29`. Only supports `channels` + `members`
  types (Slack UI limitation).
- **Last-N-days**: `slack-extract last channels --days 7`.
- **Discover supported types**: `slack-extract types`.
- **Check auth state freshness**: `slack-extract auth`.

This skill unifies three pre-existing Python scripts under one
predictable verb-based shape. Behavior is identical because both
routes drive the same Slack admin UI; this CLI exists to make the
surface agent-callable and predictable.

## When NOT to use

- **Live Slack data** (recent messages, channel inventory, user
  search): use the `slack` CLI (slack-cli package, separate
  skill). This CLI is specifically for the *analytics rollup*
  exports that Slack generates server-side.
- **Real-time monitoring**: analytics CSVs are rolled-up snapshots,
  often hours stale. For up-to-the-minute data, use slack-cli's
  `conversations history` or similar.
- **Bot-account-only queries**: analytics CSVs are gated by the
  Slack admin / org-owner role; the Playwright auth state must be
  from a user with that permission.

## Prerequisites

- **`python3` and Playwright installed**:

  ```bash
  python3 -c "import playwright" \
    || pip install playwright && playwright install chromium
  ```

- **Slack auth state** at `slack_auth_state.json` (repo root by
  default; override via `SLACK_AUTH_STATE_PATH`). Created the first
  time you run a Playwright script non-headless and complete the
  Slack login interactively. Check freshness:

  ```bash
  slack-extract auth
  # → {"status":"present","mtime":"...","age_days":1.0,"warning":null}
  ```

  Auth typically lasts ~30 days; the CLI warns when age > 30.

- **Admin role on the workspace** — analytics CSVs require Slack's
  admin/org-owner permissions.

## Subcommands

### trigger

```bash
slack-extract trigger channels
slack-extract trigger members --headless
slack-extract trigger all
```

Clicks "Export CSV" in the appropriate analytics page and exits.
The CSV is generated by Slack server-side; check your Slack workspace's
Files area for the result. **No local download.**

Supported types: `channels`, `members`, `messages`, `overview`, `all`.

### download

```bash
slack-extract download channels                       # default dir = ./analytics-downloads
slack-extract download members --headless --dir /tmp/csvs
```

Triggers + waits + downloads to local disk. Slower than `trigger`
because it waits for the browser to receive the file, but the CSV
ends up on the local filesystem ready for immediate analysis.

### dated

```bash
slack-extract dated channels --start 2026-05-01 --end 2026-05-29
slack-extract dated members --start 2026-04-01 --end 2026-04-30 --headless
```

Triggers an export scoped to a specific date range. **Channels +
members only** — the messages/overview pages don't expose a date
picker in the admin UI.

### last

```bash
slack-extract last channels --days 7
slack-extract last members --days 30 --headless
```

Convenience for "last N days ending yesterday". Internally
translates to `--start (today - N days)` / `--end (yesterday)`.

### types

```bash
slack-extract types | jq '.'
```

Enumerates the type values and notes per-mode limitations.

### auth

```bash
slack-extract auth | jq '.age_days'
```

Returns auth-state status, file mtime, age in days, and an optional
warning if age > 30. Returns `status: "missing"` + exit 4 if no
auth file present (run the underlying script once non-headless to
log in).

## Pattern: weekly Pulse rollup

```bash
# Trigger fresh exports for both channels + members
slack-extract trigger channels --headless &
slack-extract trigger members --headless &
wait

# (~minutes later, after Slack server-side generation)
# Pick up the CSVs from the Slack Files area via slack-cli
slack files list --body '{"types":"csv","count":10}' --fields "id,name,created"
```

For automated weekly rollups, the existing `backfill-slack-analytics.py`
already orchestrates this for cron usage. The CLI is the interactive /
agent-callable surface.

## Pattern: just-in-time analytics for a briefing

```bash
# At the start of a briefing-prep flow, force-refresh the last-week
# data for channels + members
slack-extract last channels --days 7 --headless
slack-extract last members --days 7 --headless

# Wait ~5 minutes for server-side CSV generation, then pull from
# Slack Files for analysis
```

## Failure modes + remediation

- **`Slack auth state not found ...`**: run the underlying script
  once non-headless to seed the auth file:

  ```bash
  cd /Volumes/main-drive/ai-PA
  python3 scripts/slack_analytics_export.py --type channels
  # Browser opens; complete Slack login; auth state is written.
  ```

- **Auth older than 30 days** (`slack-extract auth` returns a
  `warning`): re-run the above to refresh.

- **Playwright not installed**: `pip install playwright &&
  playwright install chromium`.

- **`Login redirect`** mid-script: Slack invalidated the session.
  Re-run the underlying script non-headless to re-login.

- **`Date picker not found`** (during `dated` or `last`): Slack
  redesigned the admin UI. Check the underlying script
  (`slack_analytics_with_dates.py`) for selector updates; this
  failure mode is rare but real (UI updates land every few months).
